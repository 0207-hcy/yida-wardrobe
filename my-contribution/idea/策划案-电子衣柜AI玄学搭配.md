# 电子衣柜 × AI 玄学搭配
## 黑客松 48 小时完整策划案

> **一句话定位**：一个懂玄学的电子衣柜——拍下你的衣服，让塔罗和心情替你做决定。

---

## 一、为什么是它：差异化定位

市面上电子衣柜 App 已经很多（Whering、Acloset、Stylebook、穿衣助手……）。如果定位成「AI 帮你搭衣服」，评委大概率见过同类产品。

**我们的差异点在「决策入口」上。**

- 传统工具：你想穿什么 → 我帮你搭
- 我们：你想不出来 → 塔罗 / 心情 / 幸运色替你做决定

**卖的是选择困难 + 情绪陪伴，不是搭配算法。**

这句话必须在开场 30 秒内讲清楚。讲清楚了，项目就立住了。

---

## 二、产品逻辑：一个大系统 + 六个小系统

### 2.1 三层架构

| 层级 | 名称 | 职责 | 数据流向 |
|---|---|---|---|
| 基座 | **电子衣柜（大系统）** | 单品存储、拍照上传、AI 识图打标、单品管理 | 所有小系统都从这里取数据 |
| 入口 | **六个小系统** | 塔罗 / 心情 / 天气 / 幸运色 / 颜色 / 盲盒 | 各自只负责「把模糊念头翻译成搭配约束」 |
| 大脑 | **推荐引擎** | 衣柜数据 + 约束条件 → 搭配组合 + 解读文案 | 统一处理，不区分入口来源 |

### 2.2 关键理解：小系统 = 约束生成器

六个小系统**不是并列的六个 App**，而是六个「约束生成器」。它们最终都输出**同一种东西**——一个 JSON：

```json
{
  "occasion": "日常",
  "mood": "想被治愈",
  "must_colors": ["浅紫", "奶油白"],
  "avoid_colors": ["黑"],
  "weather": "18°C 小雨",
  "vibe": "soft / cozy",
  "story": "塔罗·星星正位：今天适合温柔地对待自己"
}
```

推荐引擎拿着这个 JSON 去衣橱里筛单品 → 组搭配 → 生成解读。

### 2.3 为什么这样设计

1. **开发量骤减**：六个功能 = 一个功能 × 六种输入，引擎只写一遍
2. **可扩展**：新增第七个入口（星座 / MBTI / 血型）只需写一个约束生成器，引擎完全不用改
3. **现场好讲**：这个架构本身就是加分项，体现工程判断

### 2.4 六个小系统的实现路径

| 小系统 | 靠什么实现 | 需要外部 API 吗 | 我们要自己写什么 |
|---|---|---|---|
| 塔罗牌 | 本地 JSON + 随机抽牌 | **不需要** | 22 张大阿尔卡纳牌义 + 每张对应的 3–4 个穿搭倾向关键词 |
| 心情 | 前端情绪选择器（8 个情绪按钮） | **不需要** | 8 种情绪 → 穿搭倾向的映射表 |
| 天气 | 天气 API | **需要**（和风天气 / OpenWeatherMap） | 调用逻辑 + 天气 → 温度区间 → 品类过滤规则 |
| 幸运色 | 本地算法 | **不需要** | 按日期 + 星座/生肖推导颜色（算法可简单，重点在仪式感包装） |
| 颜色 | 前端色轮 / 色卡 | **不需要** | 选定色 → 按主色相似度匹配衣橱单品 |
| 盲盒 | 本地随机 + 抽卡动画 | **不需要** | 随机抽 1 件核心单品，再围绕它补全一套 |

**结论：6 个小系统里只有「天气」真的需要调外部接口，其余 5 个都是本地逻辑 + 内容表。不要在找 API 上浪费时间。**

### 2.5 AI 能力只用在哪两处

| 用途 | 技术方案 |
|---|---|
| 上传衣服时看图打标 | 多模态大模型：输入图片 → 输出结构化 JSON（品类 / 主色 / 风格 / 季节） |
| 搭配结果的推荐理由 | 文本 LLM：输入约束 JSON + 选中单品 → 输出「为什么这套适合今天的你」 |

**其余全部用规则实现。** 规则快、稳、不翻车。

### 2.6 技术选型速查

- **识图**：不训模型，直接调多模态大模型看图打标，一次调用搞定
- **主色提取**：前端 canvas + ColorThief，几行代码
- **天气**：免费 API（和风 / OpenWeatherMap），来不及就硬编码兜底
- **塔罗**：22 张牌义手写 JSON，不依赖 AI
- **推荐引擎**：规则约束筛候选 + LLM 写解读（先用规则保证搭配靠谱，再让 AI 讲故事）
- **结果展示**：拼贴 board，**不做图生图**

## 三、48 小时时间倒排

> **总体原则**：48 小时不是把 72 小时压缩，而是**砍掉一半功能、把省下的时间全部投给 Demo 表达**。功能只做减法，不做加法。

### Day 1（0–24h）：打通一条完整链路，丑没关系

| 时段 | 目标 | 交付物 |
|---|---|---|
| 0–3h | 定方向、冻结需求、搭项目骨架 | P0 清单确认；代码仓库 + 前端框架跑起来 |
| 3–7h | 素材收集 + 单品库搭建 | 12–15 张白底单品图 + 打标表 |
| 7–12h | 上传 + AI 识图打通 | 传一张图 → 返回结构化标签，能看到结果 |
| 12–17h | 衣柜列表页 | 预置单品能正常展示 |
| 17–22h | 第一个玄学入口（塔罗） | 点塔罗 → 抽牌 → 出搭配结果 |
| 22–24h | 复盘 + **强制休息** | 写明日任务卡；必须睡，不许通宵 |

> **Day 1 结束标准**：现场拍一件衣服 → 它出现在衣橱里 → 点塔罗能出一套搭配（哪怕丑）。
>
> **强制休息是纪律，不是建议。** 48 小时里通宵一晚，第二天效率会掉一半，得不偿失。

### Day 2（24–48h）：补入口 → 冻结 → 全部投给表达

| 时段 | 目标 |
|---|---|
| 24–28h | 心情入口 + 天气 API 接入（含硬编码兜底） |
| 28–30h | 盲盒入口（抽卡动画）——**这是最后一个功能** |
| **30h** | **MVP 冻结线，之后禁止新增任何功能** |
| 30–36h | 结果页拼贴 board 打磨、整体视觉统一 |
| 36–40h | PPT / 落地页制作 |
| 40–44h | 演示脚本定稿 + **第一次完整彩排** |
| 44–46h | 设备调试、网络预案（热点备份）+ **第二次彩排** |
| 46–48h | 提前到场，走一遍完整动线 |

> **第 30 小时 = 冻结线**（48 小时的 62%）。之后任何人提新功能一律说 No。

### 48 小时的功能取舍

| 入口 | 处置 |
|---|---|
| 塔罗 | **P0**，必做 |
| 心情 | **P0**，必做 |
| 盲盒 | **P1**，第 28–30 小时窗口做，到点没做完立刻砍 |
| 天气 | **P1**，接了更好，但必须有硬编码兜底 |
| 幸运色 | **P2**，只做 UI 占位 |
| 颜色 | **P2**，只做 UI 占位 |

## 四、三人分工

**团队构成**：1 名技术 + 2 名文科（含组长）

| 角色 | 人 | 主要负责 | 具体交付物 |
|---|---|---|---|
| **技术负责人** | 同学 A | 全部代码：前端界面、AI 识图接入、推荐引擎、六个小系统逻辑 | 可运行的产品 Demo |
| **内容与产品** | 你 | 产品定义、六大小系统内容表、单品库素材、页面文案、演示脚本、**守冻结线** | 牌义 JSON、情绪映射表、单品库、讲稿 |
| **视觉与叙事** | 同学 B | UI 视觉、结果页拼贴设计、PPT / 落地页、Demo 视频、现场表达 | 视觉稿、PPT、演示视频、路演 |

### 给文科生的两条生存法则

1. **不写代码，但要把「内容表」写成技术能直接用的格式。**
   塔罗牌义用 **JSON** 给技术同学，不要给 Word 文档。这是文科生在技术项目里最容易被浪费掉的地方。

2. **你负责守住冻结线。**
   技术同学容易陷入「想把某个功能做完美」，文科生的职责就是把节奏拉回来。**第 30 小时之后，新需求一律拒绝，包括技术同学自己提的。**

### 人手不足时的补位

- 技术同学忙不过来 → 你（产品）承担前端文案与静态页面
- 素材来不及 → 同学 B 承担抠图与视觉统一
- **没有人做纯等待的角色。**

## 五、风险预案

| 风险 | 概率 | 预案 |
|---|---|---|
| 识图效果差（照片背景乱） | 高 | Demo 用提前备好的干净照片；识图失败走「手动选标签」兜底 |
| 天气 API 调不通 | 中 | 硬编码一个天气状态，只影响一个入口，不阻塞主线 |
| **6 个入口做不完** | **极高** | 48 小时下 P0 只保塔罗 + 心情，其余四个保留完整 UI 的「敬请期待」占位，讲稿里说明是路线图 |
| **有人通宵导致 Day 2 崩盘** | 高 | 第 22–24 小时强制休息，写进群规；技术同学尤其不能熬夜 |
| 网络 / 设备故障 | 中 | 手机热点备份 + 提前录 30 秒成功演示视频作最终保底 |
| 评委问「这不就是个搭配 App 吗」 | 必问 | 准备回答：入口即产品，我们卖的是决策与情绪，不是搭配算法 |

## 七、三个必须绕开的坑

### 坑 1：网图素材风格不统一 → Demo 看起来像垃圾

方向对，但要用**白底 / 纯色底的单品图**（电商主图或品牌 lookbook 平铺图），**千万别用背景杂乱的生活照**。提前统一抠底，十张图能省两小时。

### 坑 2：想用 AI 生成「上身效果图」→ 效果崩 + 时间黑洞

**不做图生图。** 改成**拼贴 board**——把选中的单品图按上装 / 下装 / 鞋 / 配饰的配位摆在一块画布上，做成小红书那种 outfit 拼图。

视觉完全可控、半小时能实现，效果比生成图好十倍。

### 坑 3：功能贪多 → 最后没有一条完整链路能跑

**在总时长的 60% 处（即第 30 小时）冻结功能**，剩下 18 小时全部用来打磨 Demo 动线和讲稿。这条线要写进群里。

## 九、外部资源与可复用组件清单

> **总原则**：能本地化的全部本地化。**整个产品只保留「天气」一个外部依赖，且必须有兜底。** 现场网络不可靠，接口挂了不能连累主线。

### 9.1 A 档：真有现成的，直接接入

| 需求 | 现成方案 | 地址 / 调用方式 | 许可证与限制 |
|---|---|---|---|
| 塔罗牌数据 | Free Horoscope & Tarot API | `https://freehoroscopeapi.com/api/v1/tarot/cards/major` | 免费、无需 key，返回 78 张牌 JSON |
| 塔罗牌数据（备选） | GitHub `krates98/tarotcardapi` | `github.com/krates98/tarotcardapi` | MIT，78 张牌 + 高清图 + 牌义，需自行部署 Node 服务 |
| **塔罗牌面图** | Rider-Waite 1909 原版扫描 | Wikimedia Commons 搜 "Rider-Waite tarot deck" | **已进入公有领域，无版权风险**，可直接下载 |
| **天气（首选）** | wttr.in | `https://wttr.in/西安?format=j1` | **零注册零 key**，支持中文，返回 JSON |
| 天气（备选） | Open-Meteo | `https://api.open-meteo.com/v1/forecast?latitude=34.34&longitude=108.94&current=temperature_2m,weather_code` | 无需 key，每日约 1 万次 |
| 天气（备选） | 和风天气 | `https://devapi.qweather.com/v7/weather/now?location=101110100&key=KEY` | 需注册，免费版每天 1000 次 |
| MBTI 题库 | GitHub 开源题库 | 如 `github.com/WifeLike/mbti-test` 中的 `questions_standard_mbti_93.json` | 标准 93 题 JSON，直接可用 |
| MBTI 工具 | `mbti-mcp` | `github.com/wenyili/mbti-mcp` | MIT，含简化版 28 题 / 认知功能版 48 题 |

> 城市代码备忘：wttr.in 直接用中文城市名即可；和风天气西安 = `101110100`。

### 9.2 B 档：不是 API，但拿来即用

| 需求 | 方案 | 说明 |
|---|---|---|
| 盲盒抽卡动画 | LottieFiles 免费开箱 / 抽卡动画 | 导出 JSON，用 lottie-web 播放，比手写 CSS 动画快得多 |
| 抽卡音效 | 爱给网 / freesound.org | 选 CC0 授权素材 |
| 图片抠底 | `rembg`（Python 开源包） | 本地跑，免费无限次，`pip install rembg` |
| 图片抠底（备选） | `withoutbg` | 开源，`pip install withoutbg`，一行调用 |
| 主色提取 | chroma.js / ColorThief | 前端几行代码，canvas 取样 |
| 中国传统色卡 | GitHub `zhongguose` 等开源 JSON | 给「幸运色」配上有质感的色名 |

> **抠图避坑**：remove.bg 免费版只输出 0.25MP 预览图，做 Demo 完全不够用，**不要选它**，用 rembg 本地跑。

### 9.3 C 档：没有现成的，必须自己写（别去找了）

| 需求 | 为什么没有 | 工作量 |
|---|---|---|
| 幸运色算法 | 「每日幸运色」是星座类 App 自己运营编的内容，无权威数据源，也无 API | 日期 hash → 色环角度，一个函数；配文案半天 |
| 心情 → 穿搭倾向 | 完全是你产品的私有知识 | 8 行映射表 |
| 颜色 → 单品匹配 | 依赖你自己的单品库标签 | 按主色相似度排序，约 20 行代码 |
| 搭配推荐逻辑 | 依赖你的单品库 + 标签体系 | 规则约 50 行 + LLM 提示词 |

### 9.5 两个必须记住的提醒

**1. MBTI 不要做成测试题。**
70 题试卷用户要答 5 分钟，现场一定崩。入口页只放 16 个字母按钮让用户直接选类型，2 秒点完。

**2. 塔罗真正要接的不是 API，是图片。**
抽牌逻辑自己写 3 行随机数就行，牌义自己写反而更贴穿搭场景。下载 22 张公有领域牌面图存本地即可。
