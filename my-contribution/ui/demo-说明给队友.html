电子衣柜 · Demo 逻辑与内容清单

这份文档把目前原型里所有能点的东西、背后的数据、以及每条交互的来龙去脉列清楚。看这一份就够，不用去翻代码。
单文件静态原型 · 390×800 模型部分是打桩，不是真 AI 11 个页面 四个板块 · 五种入口
先说清一件事，免得开会时对不上。
这个 demo 是纯静态 HTML + JavaScript，一个文件、不联网、不调模型。凡是需要「读懂你」的地方（比如输入一句话后自动匹配），后台其实是张关键词对照表在假装 AI。
演示时请照实说是打桩——我们要证明的是交互和结构成立，不是「模型已经跑通」。

1我们做的是什么

一句话定位：一个懂玄学的电子衣柜——拍下你的衣服，让抽卡和心情替你做决定。

差异点不在搭配算法，在「决策入口」。市面上的电子衣柜都是「你想穿什么 → 我帮你搭」；我们反过来：「你想不出来 → 我替你做决定」。

这一层必须在开场 30 秒内讲明白。我们卖的是选择困难 + 情绪陪伴，不是搭配算法。讲透了，项目就立住了；讲不透，评委会觉得「这不就是个搭配 App 吗」。

2三级信息架构

抽屉 → 板块 → 入口。三层各管一件事，队友记住这三层就行。
一级 · 侧边抽屉（三个大类） ├─ 拿主意 ★★★★★ 核心 · 抽屉里唯一的 hero ├─ 我的衣柜 （配套）放单品的地方 └─ 广场 （配套）看别人怎么决定 二级 · 四个板块（点「拿主意」后挂衣杆上的四个） ├─ 抽取式 交给看不见的力量 翻牌 · 刮开 · 摇签 ├─ 调节式 说说你今天的状态 拖滑块 · 连续值 · 实时反馈 ├─ 选择式 今天你想成为谁 点卡片 · 明确的主动决策 ├─ 输入式 直接告诉它 打字 · 实时匹配 └─ ＋ 再加一个 虚线空位 → 点进去解释「板块可插拔」 三级 · 具体入口（板块页里的卡片） └─ 塔罗牌 / 刮刮乐 / 盲盒（灰） / 抽签（灰） … 灰卡 = 这一版演示不做，用来证明「还能往上挂」

为什么第二个大类叫「拿主意」而不是「帮我搭配」

  • 这一层做的事是「选一种决定方式」，不是「AI 直接出搭配」。叫「帮我搭配」，用户点进去看到四个分类会落差。
  • 另外两项（我的衣柜 / 广场）都是名词，「拿主意」是动词短语，三者在抽屉里排在一起更整齐。
  • 备选名：今天听谁的 / 今天怎么定 / 挑个方式 / 决定台。

核心只有一个，另外两项怎么被「降级」的

没有给「拿主意」加特效，靠的是把另外两项压下去：抽屉里「拿主意」是 hero 卡片（大图标 + 大字 + 紫色底），下面一条分隔线 +「配套」标签，「我的衣柜」「广场」是小号灰字。视觉分级一做，主次自然就出来了。

抽屉项样式说明文案层级
拿主意hero · 紫色底 16px 粗体抽 · 拖 · 点 · 说，选一种定今天主入口
我的衣柜sub · 灰色 12.5px放单品的地方配套
广场sub · 灰色 12.5px看别人怎么决定配套

抽屉底部固定一句：「我们不做推荐。我们只帮你把今天定下来。」

所有入口最后都汇到同一页

塔罗牌→刮刮乐→能量条→身份扮演→命令栏 → 统一产出「约束条件」→ 结果页

这是整个架构最关键的一点：入口只负责把模糊念头翻译成约束，出搭配只有一套引擎。加第七个板块不用改引擎。

每个板块 = 一种「交互范式」。四页各有各的体感，故意不做得一样。

为什么不把四页全做成塔罗翻卡？
如果四个板块都翻牌，就等于自己推翻了「我们不全是抽卡」这句话，评委会问「那你这四个有什么区别」。
所以改成各留各的体感：翻牌 / 拖条 / 选卡 / 打字——每种交互点一下就知道不一样，这本身就是差异化证据。

5五个页面里到底装了什么（数据层）

队友改文案、加内容，只需要动这五张表。下面是每张表的字段和作用。

① 挂衣杆上的板块 · BOARDS

首屏那根杆上的东西。每件衣服是一个 SVG，点它进对应板块。共 5 个槽位（4 板块 + 1 空位）。

字段含义
k / t / s板块名 / 一句话标题 / 补充说明
how交互范式标签（翻牌·刮开·摇签…）
c/b/fg/line/dk该板块的专用色（底/边/字/线/深字），四板块各一套
shape挂在杆上的衣服图形：抽绳袋 / 腰带 / 外套 / 吊牌 / 虚线框
items该板块下的入口卡（名称 + 说明 + 能不能点 + 跳到哪）

② 天气 · CITIES（全 App 唯一的「自动注入」）

天气不进任何板块，它挂在首屏顶部当一个芯片，平时零操作。点一下才展开城市弹层。

城市天气它只决定一件事
西安（默认）18℃ 阴薄外套
北京9℃ 晴加一件
上海21℃ 多云单层就够
成都16℃ 小雨带伞 + 薄外套
广州29℃ 闷热越薄越好
哈尔滨2℃ 风大羽绒
换城市的规则（重要，别改）：换城市只改「厚薄」这一档，不动风格、不动颜色。
理由是天气不该抢走用户的决定权——它只是个兜底背景。
弹层顶部还有一个「用当前位置」，点它就是自动读取、完全不用管它。

输入后输出两块：「从这句话里读到」= 命中的标签组；「匹配到的方向」= 结果卡（第一条高亮，第二条可以跳去身份扮演，第三条永远留「不想选，就抽一张」）。

6一条搭配是怎么出来的

四个入口看起来完全不同，但走到底都是同一套动作。

步骤发生了什么举例
1 · 收集意图入口用它的方式问出用户状态抽到「星星」/ 电量 34% / 选了「学姐」/ 打了「今天好累」
2 · 生成约束翻译成三个条件：风格 · 主色 · 避雷色，并写一句摘要风格 文艺 · 色系 浅蓝/米白 · 避雷 纯黑
3 · 筛单品按「风格命中 +4 分、颜色命中 +2 分、避雷色 -9 分」排序从 10 件里挑出分最高的
4 · 补齐一套按品类占位：上装 + 下装 + 鞋 + 配饰（若最高分是连衣裙，就换成 连衣裙 + 鞋 + 外套 + 配饰）固定出 4 件
5 · 出结果结果页显示：约束摘要 + 四件拼贴 + 来源徽章 +「来自「塔罗·星星」的解读」—

「换一套」怎么工作：把当前这套里随机一件记进「排除名单」，再重算一次，保证换出来的不一样。换板块则回到首屏。

给队友的一句话：入口是四个，引擎只有一个。同学 A 只要把这套规则写一遍，后面接几个入口都不用重写。

7全站共用的受控词表

所有入口必须用同一套词汇，不许各写各的——否则同一个颜色在不同地方写两个名字，筛选会出错。

8 种风格 简约通勤文艺甜美运动复古明艳慵懒
24 个色（策划口径） 奶油白米白纯白燕麦焦糖浅蓝牛仔蓝雾紫藕粉玫粉正红酒红亮黄炭灰纯黑银灰…
7 个品类 上装下装外套连衣裙鞋配饰包
口径对齐提醒：「8 风格 / 24 色 / 7 品类」是策划案里定的目标口径。目前 demo 实际用到的是：8 种风格（都在用）、6 个品类（包还没做）、约 16 个具体色值。
补内容时按目标口径补齐，但写代码的同学要知道现在实装到哪一步。

10还没最终拍板的两件事

  • 抽屉三个名称是否就这样定（拿主意 / 我的衣柜 / 广场）。
  • 入口墙上的灰色卡片是否收掉。现在的处理是保留——因为它能说明「板块还能往上挂入口」，比空着更有说服力。
