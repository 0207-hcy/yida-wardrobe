## A. 项目描述（简历项目栏 / 作品集，约 160 字）

**易搭 YIDA · 电子衣橱 × 穿搭灵感（个人项目 · H5 + Android）**
面向移动端的本地优先穿搭应用：五种玩法采集当日状态，规则引擎从衣橱组合出 4 套搭配并生成结果与海报，另有微博式广场与个人主页。采用无构建工具的原生前端架构（经典脚本 + IIFE），双 IndexedDB 做数据隔离与本地持久化，`file://` 双击即可离线运行；通过 Capacitor 6 复用同一套 H5 编译为 Android APK。用 Playwright 编写三轮共 118 项自动化回归，覆盖玩法全链路、边界输入、备份校验与打包一致性，0 失败。
**技术栈**：Vanilla JS / CSS 变量双主题 / IndexedDB / Canvas / Capacitor 6 / Gradle (JDK17 · SDK35) / Playwright
**职责**：独立完成前端架构、玩法与推荐引擎、数据层、安卓壳接入、自动化验证与交付文档。

## B. 简历 bullet（按岗位挑 3–5 条）

- 设计**零构建工具**的前端架构（经典脚本 + IIFE 全局命名空间 + CSS 变量双主题），规避 `file://` 下 ESM / fetch / canvas 跨域三禁，实现双击即用与离线可玩。
- 将塔罗牌、社交电量、身份扮演、跃然搭配、灵感签 **5 类玩法抽象为统一 context**，由单一引擎出口产出受控 8 风格约束、季节过滤与避色规则，生成 4 套组合并贯穿结果 / 历史 / 详情 / 海报 / 推荐理由 5 个消费端。
- 用**双 IndexedDB + CSS 命名空间纪律**隔离主应用与广场状态，配套哈希零污染校验；实现备份导出 / 恢复 / 清空与白名单校验，个人数据全程不出端。
- 设计**上传双模式**：本地服务可用时走抠图打标，App / 离线时自动降级为「保留原背景 + 手动核对标签」，元数据如实标注，不把原图伪装成 AI 识别结果。
- 接入 **Capacitor 6** 打包 Android，沉淀 `sync-www → cap sync → assembleDebug` 三步重编与 APK 内容自检（132 条 assets、源码 / www / 公开仓 / APK 四处逐字节一致），解决「Gradle 成功但 APK 未更新」的假成功问题。
- 编写 **Playwright 自动化回归 118 项（78 + 12 + 28）**，0 FAIL，覆盖五玩法全链路、越界输入、备份白名单、`file://` 与 HTTP 双协议、广场 / 主页零污染。

## C. 面试口述（60 秒）

「这是一个我独立做的移动端穿搭应用，最核心的取舍是**本地优先 + 零构建**。所有个人照片和记录都放在 IndexedDB，没有账号、没有云端调用，所以双击 HTML 就能跑，也方便用 Capacitor 直接套成安卓壳。玩法有五种，我没有给每种玩法写一套推荐逻辑，而是把用户输入统一抽象成 context，由一个引擎出口产出风格约束和组合，这样结果页、历史、海报、推荐理由读的是同一份语义。工程上踩得最深的是 `file://` 协议限制和 Capacitor 打包的『假成功』，我都用可复跑的自动化回归兜住了：三轮 118 项，0 失败。另外一个我比较坚持的点是**语义诚实**——离线时没有抠图能力，就明确告诉用户『这张图保留原背景、标签请手动核对』，不把本地处理包装成 AI 识别。」

## E. 高频追问准备

| 问题 | 要点 |
|---|---|
| 为什么不用 Vue / Vite？ | 硬约束是「双击 HTML 就能用」+「同一套代码进 Capacitor WebView」。`file://` 下模块脚本不执行、fetch 被拒，引入构建工具会直接破坏离线场景；代价是手动管理脚本顺序与全局命名空间，用 IIFE + 命名空间前缀约束。 |
| AI 在哪里？ | **如实说**：本项目主体是离线玩法与规则引擎，没有云端大模型；打标是可选的本地图像处理服务，不可用时降级为人工核对。不把本地统计或规则结果包装成 AI 识别。 |
| 数据怎么迁移 / 多端同步？ | 目前 intentionally 不做多端：用备份导出 JSON / 恢复实现手工迁移，并做白名单校验防止脏数据。若要同步，下一步是加账号与端到端加密，但会牺牲「无账号」这个隐私前提。 |
| 安卓踩过什么坑？ | ① 只同步 `www` 不跑 `cap sync`，Gradle 显示成功但 APK 没新文件；② 中文路径触发 AGP 非 ASCII 检查；③ `adb` / `aapt` 读不了中文路径，需先复制到纯 ASCII 临时目录；④ JDK / SDK 版本与 Capacitor 主版本绑定。 |
| 如果重做会改什么？ | 引入类型约束与模块边界（但仍保持无运行时构建）、把规则数据外置为可配置的 JSON、给图片资源做体积优化与懒加载。 |
